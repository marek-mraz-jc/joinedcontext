# daiya Design Decisions (Better Over Faithful)

- **Canonical `BTreeMap` storage for unknown JSON fields (`daiya-model`)**: Replaces Grafana's unordered Go `map[string]any` with `BTreeMap<String, Value>` at every schema level so `export(import(f))` is deterministic and byte-stable by construction without losing unknown fields.
- **DNS-pinned outbound guard with IPv4-mapped IPv6 normalization (`daiya-query`)**: Replaces Grafana's optional `data_source_proxy_whitelist` (which checks hostnames before connect and is vulnerable to DNS rebinding) with a mandatory per-datasource host allow-list that resolves DNS once, rejects loopback/private/link-local/CGNAT/metadata IPv4 and IPv4-mapped IPv6 addresses, and pins the validated socket addresses on the HTTP client.
- **Iterative depth-bounded PromQL & SQL macro/template interpolation (`daiya-query`)**: Replaces Grafana's raw string replacement for template variables with context-aware escaping (PromQL regex/literal escaping and single-SELECT read-only view verification after comment stripping) so template variables cannot inject query syntax across languages.
- **Hashed 256-bit public dashboard tokens with org/version-bound cache keys (`daiya-api`, `daiya-query`)**: Replaces Grafana's plaintext `access_token` column and uncached public queries with SHA-256 hashed tokens compared in constant time, strict rejection of any caller-supplied query/target/expression/variable payload on public endpoints, and a cache key bound to `(org_id, instance_id, dashboard_uid, dashboard_version, panel_id, range_bucket)`.
- **Cryptographic `state_etag` in `plan`/`apply` (`daiya-import`)**: Replaces blind `overwrite: true` provisioning with a SHA-256 digest of the organization's live dashboard/folder/datasource state embedded in every plan bundle and verified before `apply` (refusing stale plans with exit code 3 / HTTP 409). `Plan` keeps its bundle server-side (`cr_plan`, keyed by organization and the SHA-256 of the canonical `{ baseEtag, desired }`, kept one hour); `Apply` takes only that digest and writes the whole bundle in one store transaction (`DaiyaStore::apply_bundle`), re-checking the etag under the organization's quota-row lock, so a bundle the reviewer never saw cannot be applied and a failure or a concurrent Apply leaves no partial state.
- **Single operation registry driving OData 4.01 CSDL and the CLI (`daiya-model`, `daiya-api`, `daiya-server`)**: Replaces Grafana's separate REST, gRPC, and provisioning code paths with one declaration table where OData and the CLI execute the same handler and `Authorizer` check.
- **No MCP door of daiya's own (review S9-29)**: the hand-written `GET /mcp/tools` and `POST /mcp/call` pair and the `daiya-mcp` crate are gone. No MCP client spoke that pair and nobody could sign in to it in jc; an MCP client reaches dashboards through the Portal's signed MCP. A path daiya does not serve answers 401 to an unsigned caller and 404 to a signed one.
- **Every request names its Organization (review S9-30)**: `X-Grafana-Org-Id` (or `X-Daiya-Org-Id`) names it, or the caller holds exactly one. Otherwise the answer is 401; no Organization stands in for a missing one. The server administrator is a member only of the Organization it names. `/d/{uid}` takes it from `orgId`.
- **A public dashboard reads only Endpoints (review S9-18)**: its panels read NGSI-LD and OData datasources at the host's own gateway Endpoints, with no token, so the Endpoint's public Policy decides what an anonymous viewer gets and publishing data stays a Change of the Endpoint. Publishing a dashboard with another source is refused with 422 naming the datasources; a panel whose source changed after publishing answers a fixed 403. `share: email` is refused.
